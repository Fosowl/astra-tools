### Source of Truth

- `asp.yaml` — The analysis specification. Read this first.
- `universes/` — Decision selections (one YAML per universe)

### Project Layout

```
asp.yaml                    # Specification: problem, decisions, inputs, outputs
CLAUDE.md                   # This file — conventions and project context
universes/
  baseline.yaml             # Default decision selections
steps/                      # Implementation (one folder per chunk)
  <chunk>/
    PLAN.md                 # Implementation notes: approach, libraries, decision mapping
    ...                     # Code files
workflows/                  # CWL workflow definitions (optional)
results/<universe_id>/      # Output files, organized by universe
```

### Building a Chunk

When implementing a chunk:

1. Create `steps/<chunk>/` for the implementation
2. Write `steps/<chunk>/PLAN.md` documenting your approach — what libraries,
   how decisions map to code, data flow, key implementation choices
3. Implement the code in that directory
4. Link the plan in asp.yaml: set `plan: steps/<chunk>/PLAN.md` on the chunk
5. Write results to `results/<universe_id>/<path>` matching output declarations
6. Validate: `asp validate asp.yaml`

For single-chunk analyses, use `steps/` directly (or `steps/main/`).

### Writing Results

Outputs and artefacts in `asp.yaml` declare a `path` field. Write result files
to `results/<universe_id>/<path>`:

| Output type | Format | Example |
|-------------|--------|---------|
| metric | JSON | `{"value": 0.95}` |
| figure | PNG, SVG, PDF | `results/baseline/confusion_matrix.png` |
| table | CSV | `results/baseline/deg_table.csv` |
| data | Parquet, CSV, HDF5 | `results/baseline/processed_data.parquet` |
| report | Markdown | `results/baseline/summary.md` |

### Keeping the Spec in Sync

If you change decisions, outputs, or analysis structure, update `asp.yaml` to
match. Run `asp validate asp.yaml` after changes.
